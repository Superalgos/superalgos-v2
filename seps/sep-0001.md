- Status: Accepted
- Criteria: 8/16 done

## Motivation

v1 died of untestable code and an unauthenticated surface; v2 must be safe to run with real money from day one.

## Criteria

- [x] SEP-1.1: Repository licence file is Apache-2.0.
  Probe: file: LICENSE is Apache-2.0. Pass: exact. Tool: Read.
- [x] SEP-1.2: `uv run pytest` passes with coverage ≥ 80% enforced by `fail_under` in `pyproject.toml`.
  Probe: test: pytest with coverage gate. Pass: ≥ 80%. Tool: uv run pytest.
- [x] SEP-1.3: `uv run mypy --strict` reports 0 errors on the engine package.
  Probe: static: mypy strict. Pass: 0 errors. Tool: uv run mypy.
- [ ] SEP-1.4: CI blocks a PR when any required check fails.
  Probe: Holds when SEP-1.5 to SEP-1.7 all hold.
- [ ] SEP-1.5: A PR with a lint error gets a red required check.
  Probe: ci: PR with lint error. Pass: red required check. Tool: gh pr checks.
- [ ] SEP-1.6: A PR with a type error gets a red required check.
  Probe: ci: PR with type error. Pass: red required check. Tool: gh pr checks.
- [ ] SEP-1.7: A PR with a failing test gets a red required check.
  Probe: ci: PR with failing test. Pass: red required check. Tool: gh pr checks.
- [x] SEP-1.8: Anti: any state-changing or admin endpoint responds 2xx to a request with no valid session or signature, except SIWE nonce issuance (bounded, single-use, rate-limited per IP) (the public relay websocket stays open by design for zero-power clients, SEP-3.43; publishing there requires a signed, delegated event).
  Probe: http: unauthenticated request to each endpoint. Pass: all 401/403. Tool: curl -i.
- [x] SEP-1.9: Anti: `eval(`, `exec(` or `new Function(` appears in first-party source.
  Probe: grep: search source for eval/exec/new Function. Pass: 0 hits. Tool: rg.
- [x] SEP-1.10: Anti: the codebase contains any code path that transfers SA tokens from a treasury or pays contributors in SA.
  Probe: grep: search for token-transfer / contributor-payment paths. Pass: 0 hits. Tool: rg.
- [x] SEP-1.11: Anti: a private key or mnemonic is written to disk unencrypted.
  Probe: test: key store writes ciphertext only. Pass: no plaintext key in files. Tool: pytest.
- [ ] SEP-1.12: A fresh self-hosted install runs one provider strategy plus one follower bot on a 4-core / 4 GB machine for 24 hours without a restart.
  Probe: soak: provider + follower on 4c/4GB for 24 h. Pass: 0 restarts. Tool: systemd/docker logs.
- [x] SEP-1.13: Anti: any server-side component stores or receives a user's exchange API secret or wallet private key.
  Probe: grep+test: server code and requests for secrets. Pass: 0 hits; server rejects secret fields. Tool: rg + pytest.
- [ ] SEP-1.14: One published container image runs on both linux/arm64 (Raspberry Pi 4/5 class, 64-bit OS) and linux/amd64 (VPS), and `sa demo` passes its smoke test on each.
  Probe: ci: multi-arch image build + `sa demo` smoke on arm64 and amd64. Pass: both PASS. Tool: docker buildx + CI runners.
- [ ] SEP-1.15: An install upgrades to a new release with one command and no git checkout, keeping keystore, strategies and history; a failed upgrade rolls back to the previous version.
  Probe: e2e: upgrade N-1 → N, then a forced-failure upgrade. Pass: data intact; failure rolls back. Tool: pytest + docker.
- [ ] SEP-1.16: After a power cut or reboot, the follower bot restarts unattended, reconciles its open positions and orders with the exchange, and executes signals released while it was down or reports each one it skipped.
  Probe: e2e: kill -9 follower with an open position, release 2 signals, restart. Pass: position reconciled; signals executed or listed as skipped. Tool: pytest + Nautilus sandbox.
