# SEP-17: Discovery (relays and providers)

- Status: Draft
- Criteria: 0/6 done

## Motivation

A follower must find providers and the relays they publish to without a central registry or a hand-pasted URL. Nostr has no root relay; discovery comes from users publishing where they are. In social trading the track record is the directory.

## Criteria

- [ ] SEP-17.1: The dashboard lists providers ranked by their verified record (scored from signed, anchored signals as `sa record` computes them), not by self-reported numbers; a provider with no verifiable history appears unranked.
  Probe: test+browser: two providers with fixture histories, one with none. Pass: order equals `sa record` scores; no-history provider unranked. Tool: pytest + bun test + Chrome.
- [ ] SEP-17.2: Each provider publishes a NIP-65 relay list (kind 10002); a follower given only a provider pubkey and one seed relay finds the provider's relays from that list and follows it.
  Probe: integration: provider on relay B, 10002 on seed relay A; follower knows only pubkey + A. Pass: follower connects to B and receives a signal. Tool: pytest + two sarelays.
- [ ] SEP-17.3: The CLI and dashboard ship a seed relay list (production `superalgos.org`) that the user can edit or replace; no code path treats any relay as required or as a root.
  Probe: grep+test: relay defaults in code, compose, docs; edited seed list. Pass: one seed list source; edited list used; no hard-coded required relay. Tool: rg + pytest.
- [ ] SEP-17.4: A provider can publish a kind 0 profile with a NIP-05 name; the dashboard shows the name as verified only when the NIP-05 lookup returns the provider's pubkey.
  Probe: test: NIP-05 JSON matching, mismatching, unreachable. Pass: verified only on match. Tool: pytest (fake HTTP).
- [ ] SEP-17.5: Anti: a zero-power or allocating follower becomes discoverable (profile, relay list or follow list published) without an explicit opt-in.
  Probe: test: full follower setup with defaults. Pass: no kind 0/3/10002 published by the follower. Tool: pytest + fake relay log.
- [ ] SEP-17.6: Social discovery events (kinds 0 and 10002) are read from general-purpose Nostr relays; sarelay's accepted kinds stay unchanged unless this SEP records why.
  Probe: grep+test: sarelay accepted-kinds list; publish kind 0 to sarelay. Pass: list unchanged; kind 0 `blocked:`. Tool: rg + go test.
