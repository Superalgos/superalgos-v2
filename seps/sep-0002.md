# SEP-2: SA identity

- Status: Accepted
- Criteria: 4/7 done

## Motivation

Earlier Superalgos work (2022) authenticated with web3 wallets; v2 makes the SA address the one identity, so token power and reputation attach to the same key.

## Criteria

- [x] SEP-2.1: A user signs in with an EIP-4361 message signed by their EVM wallet, and the server derives the session identity from the recovered address.
  Probe: test: SIWE login round trip. Pass: session = recovered address. Tool: pytest.
- [x] SEP-2.2: A sign-in with an expired or replayed nonce is rejected.
  Probe: test: replayed / expired nonce. Pass: rejected. Tool: pytest.
- [x] SEP-2.3: The SA identity can sign a delegation for a device key with an expiry, and a verifier accepts signals from that device key only within the expiry.
  Probe: test: delegation within expiry. Pass: accepted. Tool: pytest.
- [x] SEP-2.4: A signal signed by a device key with a revoked or expired delegation fails verification.
  Probe: property: expired/revoked delegation. Pass: always rejected. Tool: hypothesis.
- [ ] SEP-2.5: Token power reflects on-chain SA holdings.
  Probe: Holds when SEP-2.6 to SEP-2.7 all hold.
- [ ] SEP-2.6: Token power for an identity equals the sum of its SA balances on every chain in the chain registry (today BSC `0xfb981ed9a92377ca4d75d924b9ca06df163924fd`, Ethereum `0xc17272c3e15074c55b810bceba02ba0c4481cd79`, and zkSync, which v1 also read and paid out on).
  Probe: integration: balance sum vs BscScan + Etherscan values. Pass: equal. Tool: pytest + RPC.
- [ ] SEP-2.7: A balance change on-chain is reflected in token power within 1 hour.
  Probe: integration: transfer, then re-read token power. Pass: updated ≤ 1 h. Tool: pytest + testnet.
