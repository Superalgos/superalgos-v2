# SEP-11: Mobile steering app

- Status: Draft
- Criteria: 0/4 done

## Motivation

The bot runs on the user's own SBC or VPS, never on the phone (no Nautilus mobile build, OS background limits, keys on a hot device); the phone is how the user watches and steers it.

## Criteria

- [ ] SEP-11.1: The mobile app signs in with the user's SA wallet and talks only to the user's own box over an authenticated, encrypted channel; it shows bot status, positions and provider track records, and pauses or resumes a bot.
  Probe: e2e+device: phone signs in, reads status, pauses a bot. Pass: bot paused on the box. Tool: Expo/emulator + pytest.
- [ ] SEP-11.2: Anti: the mobile app stores, displays or transmits an exchange API secret or the funds key.
  Probe: grep+test: app source and traffic for secret fields. Pass: 0 hits; box refuses secrets to the app. Tool: rg + mitm capture.
- [ ] SEP-11.3: A bot failure (stopped, exchange disconnected, signal skipped) reaches the phone as a push notification within 60 s, with the payload encrypted end to end so the push service cannot read it.
  Probe: e2e: kill the follower on the box. Pass: encrypted push received ≤ 60 s. Tool: emulator + pytest.
- [ ] SEP-11.4: The phone pairs with the user's engine by scanning a one-time QR code shown by the setup wizard; pairing yields a revocable device credential bound to the SA identity, and an unpaired client gets 401 on every management endpoint. (after: SEP-12.6)
  Probe: e2e: pair via QR token, call status; revoke; call again; unpaired call. Pass: 200, then 401, 401. Tool: pytest.
