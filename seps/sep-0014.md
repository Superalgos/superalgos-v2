# SEP-14: Follower risk controls

- Status: Accepted
- Criteria: 0/5 done

## Motivation

v1 had balance caps but no risk concept in 2,099 doc pages; nobody should follow a stranger with real money without limits. Required before live trading (SEP-12.5).

## Criteria

- [ ] SEP-14.1: A follower sets, per followed provider, a spend cap (percent of balance) and a minimum and maximum balance; an order that would breach them is not placed and the ledger says which limit stopped it.
  Probe: test: orders breaching spend cap / min / max balance. Pass: not placed; ledger names the limit. Tool: pytest.
- [ ] SEP-14.2: A follower sets a daily loss limit (absolute or percent); once reached, the bot stops opening positions until the next UTC day or a manual resume, and says so in its status.
  Probe: test: losses reaching the daily limit; next UTC day. Pass: stops opening; resumes next day or manually. Tool: pytest (fake clock).
- [ ] SEP-14.3: An execution error (exchange reject, reconciliation mismatch, missing data) pauses the affected provider's follow after a configurable count, instead of retrying blindly; resume is explicit.
  Probe: test: N injected execution errors. Pass: provider follow paused; explicit resume. Tool: pytest.
- [ ] SEP-14.4: A kill switch (CLI, dashboard, and later the mobile app) cancels open orders and stops all following in one action, and survives a restart (the bot comes back stopped).
  Probe: e2e: kill switch, then restart. Pass: orders cancelled; bot comes back stopped. Tool: pytest + process restart.
- [x] SEP-14.5: A follower's profile (`<home>/profile.json`, closed schema) holds a disaster stop, default 10%, 0 = off, refused outside (0, 50]: after each entry fill one stop-limit rests at the exchange at the average entry price x (1 - pct), its limit a named offset below the trigger, sized to the whole position, replaced when the position size changes and cancelled when flat. Every sell the follower sends (a close or a triggered emulated stop, SEP-3.45) cancels it first and goes out after the cancel is confirmed; a cancel that fails reports the unsent sell. With 0 no order reaches the exchange. The venue order id and how each stop ended are in the follower's summary.
  Probe: test + property: `packages/sa-engine/tests/test_follower_stops.py` (Hypothesis over random entry fills, partial closes, stop triggers and cancels on a venue that rejects a sell while a stop-limit rests), `apps/sa-cli/tests/test_profile.py` (default, set, off, invalid), then one live testnet run (`demo-testnet.sh`). Pass: at most one stop-limit rests, its quantity is the position, none rests when flat, no sell is submitted while one rests; the testnet run shows the stop-limit's order id, its cancel, then the market sell filled. Tool: pytest + Binance spot testnet. Evidence: `test_follower_stops.py`, `test_profile.py`; Binance spot testnet run 2026-10-19: two stop-limits at -10% accepted with order ids, each cancelled before its market close filled.
