# SEP-4: Strategy authoring and backtest

- Status: Accepted
- Criteria: 3/7 done

## Motivation

Keeps v1's best idea, the typed node model for strategies, without its `eval` and canvas coordinates.

## Criteria

- [ ] SEP-4.1: A strategy is a typed JSON document (schema derived from v1's Trading System → Strategy → stages → Conditions model) validated by a JSON Schema in CI.
  Probe: ci: strategy schema validation. Pass: all fixtures valid. Tool: jsonschema.
- [x] SEP-4.2: A strategy document can hold multiple concurrent orders (a 10-level grid is one strategy, not ten).
  Probe: test: 10-level grid as one document. Pass: validates + backtests. Tool: pytest.
- [x] SEP-4.3: A strategy document compiles to a Nautilus strategy and backtests over at least 1 year of 1-minute data on one market.
  Probe: integration: 1-year 1m backtest. Pass: completes. Tool: Nautilus backtest.
- [x] SEP-4.4: An LLM-authored strategy that fails schema validation is rejected with the failing path in the error.
  Probe: test: invalid LLM output. Pass: rejected with path. Tool: pytest.
- [ ] SEP-4.5: A user defines a new indicator as a typed document composed from the safe DSL (streaming, one value per bar, no eval), and a strategy uses it by name; backtest, live and the chart compute it through the same code path.
  Probe: test: user indicator in strategy: backtest vs live replay vs API series. Pass: identical values. Tool: pytest.
- [ ] SEP-4.6: A strategy pins each user-defined indicator by content hash, and recomputing a track record fails with the indicator's name when the definition no longer matches the hash.
  Probe: test: edit a pinned indicator, recompute record. Pass: fails naming the indicator. Tool: pytest.
- [ ] SEP-4.7: Anti: a user-defined indicator that reads an unclosed or future bar passes validation (property test).
  Probe: property: random indicator definitions vs bar time. Pass: never reads an unclosed bar. Tool: hypothesis.
