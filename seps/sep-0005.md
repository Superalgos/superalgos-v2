# SEP-5: Visual designer

- Status: Implemented
- Criteria: 17/17 done

## Motivation

The part the community remembers; it edits the same strategy document, so the designer is a view, not the source.

## Criteria

- [x] SEP-5.1: The strategy schema expresses v1's event logic: a situation is an AND of conditions, an event is an OR of situations, first match wins (tested against v1's documented semantics).
  Probe: test: situation/event fixtures from v1 semantics. Pass: identical firing. Tool: pytest.
- [x] SEP-5.2: Order rate, order size, stop and target accept numeric formulas evaluated by the safe DSL (no eval); invalid formulas are rejected with their JSON path and column.
  Probe: property: random formulas; invalid ones. Pass: evaluated safely; errors carry path+col. Tool: hypothesis.
- [x] SEP-5.3: The manage stage holds ordered phases for stop and target, each with a formula and next-phase / move-to-phase events; timing rules (orders fill from the next bar; stop is checked before target on the same bar) are documented and tested.
  Probe: test: phase transitions and same-bar stop/target. Pass: documented rule holds. Tool: pytest.
- [x] SEP-5.4: Orders have create and cancel events and can re-arm, so a 10-level ladder is one strategy whose backtest re-places filled levels.
  Probe: test: 10-level ladder backtest. Pass: filled levels re-placed. Tool: pytest.
- [x] SEP-5.5: Formulas and conditions can reference another timeframe (e.g. `ema(20, "4h")`) without look-ahead (property test).
  Probe: property: higher-timeframe refs vs bar time. Pass: never uses an unclosed bar. Tool: hypothesis.
- [x] SEP-5.6: The designer opens every example strategy and saves it back byte-identical when nothing changed.
  Probe: test+browser: open/save each example. Pass: byte-identical. Tool: bun test + browser (Chrome).
- [x] SEP-5.7: From the designer a user runs a backtest (loopback-only endpoint, bounded time) and opens its result on the chart.
  Probe: e2e+browser: designer → backtest → chart overlay. Pass: report shown on chart. Tool: pytest + browser (Chrome).
- [x] SEP-5.8: The designer's formula editor shows server-side DSL errors at the right node and column.
  Probe: browser: bad formula in editor. Pass: error at node and column. Tool: browser (Chrome).
- [x] SEP-5.9: The designer loads a strategy document, edits a condition, saves, and the saved document validates against the schema.
  Probe: browser: edit and save a condition. Pass: saved doc validates. Tool: browser (Chrome).
- [x] SEP-5.10: Anti: the strategy document contains canvas layout data (positions live in a separate view file).
  Probe: grep: strategy files for position keys. Pass: 0 hits. Tool: rg.
- [x] SEP-5.11: The designer stays interactive (input latency < 100 ms) with a 200-node strategy in a real browser.
  Probe: browser: 200-node strategy interaction. Pass: < 100 ms. Tool: browser (Chrome).
- [x] SEP-5.12: The designer's default view is the v1-style radial graph: per-type v1 icons, status rings, and dashed parent–child lines whose dashes travel toward the parent.
  Probe: browser: open each example. Pass: radial view with v1 icons, moving dashes. Tool: browser (Chrome).
- [x] SEP-5.13: In the radial view each node's place is set relative to its parent (spread of its children, distance, drag-to-pin); moving a node carries its subtree, and the settings survive a reload and a Save view / Load view round trip.
  Probe: test+browser: spread, distance, drag, reload, view round trip. Pass: positions relative to parent persist. Tool: bun test + browser (Chrome).
- [x] SEP-5.14: Anti: changing the radial layout changes the strategy document (bytes identical, no undo entry).
  Probe: test: radial edits. Pass: strategy bytes identical, undo empty. Tool: bun test.
- [x] SEP-5.15: Radial settings stay on the same order or situation when a sibling is inserted above it (keyed by order `id` / situation `name`).
  Probe: test: insert order above configured one. Pass: settings follow the order. Tool: bun test.
- [x] SEP-5.16: Nodes collapse and expand with a hidden-descendant count; strategies over 40 nodes open with situations collapsed.
  Probe: test+browser: collapse/expand, 93-node example. Pass: counts shown, default collapse. Tool: bun test + browser (Chrome).
- [x] SEP-5.17: The node context menu stays fully inside the viewport wherever it is opened.
  Probe: test+browser: right-click near each edge. Pass: menu inside viewport. Tool: bun test + browser (Chrome).
