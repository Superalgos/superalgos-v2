# SEP-13: Indicators (data mining, v1 parity)

- Status: Draft
- Criteria: 0/6 done

## Motivation

The indicator is the unit: each indicator is its own package with a category (trend, momentum, volatility, volume, pattern; later on-chain, sentiment). A v1-style data mine is at most a curated list of indicators. Three layers: built-in (engine, Python; NautilusTrader's ~40 Rust indicators where one exists), composed (strategy DSL, SEP-4.5 to SEP-4.7), coded (WebAssembly, sandboxed, later). Shared by hand as JSON first, then as signed, content-addressed Nostr events (marketplace).

## Open questions

- Coded indicators in Rust. Our own: Rust compiled natively (PyO3 extension, shipped in the multi-arch wheels and image) and plugged into Nautilus as a Python `Indicator` subclass (`handle_bar`, registered with `register_indicator_for_bars`). Community and marketplace: the same Rust source compiled to WebAssembly and run sandboxed, since native code from strangers cannot be trusted. Open: WASM runtime, cross-platform determinism, per-bar resource limits, how a strategy pins a module, and whether Nautilus's Rust `Indicator` trait can be used directly (not verified).
- Non-candle data sources (v1 sensors: funding rates, Fear and Greed, on-chain): Sensor interface and storage shape.

## Criteria

- [ ] SEP-13.1: Every built-in indicator declares a category, typed params with defaults and named outputs, and matches a reference implementation (TA-Lib or the published formula) within tolerance on a fixed candle set.
  Probe: test: each built-in vs reference on a fixed 1m set. Pass: max abs diff ≤ 1e-9 relative. Tool: pytest + TA-Lib reference.
- [ ] SEP-13.2: Every NautilusTrader indicator (~40 in 1.231: moving-average family, Ichimoku, MACD, Stochastics, RSI, CCI, Aroon, DMI, ATR, Bollinger, Keltner, Donchian, VWAP, OBV, Klinger, candle patterns, Swings and the rest) is available as a built-in through the same interface, with one code path for chart, backtest and live (SEP-8.2).
  Probe: test: indicator registry vs list; chart = backtest = live. Pass: all present; identical series. Tool: pytest.
- [ ] SEP-13.3: A composed indicator may reference its own previous output (`prev(out, n)`), enough to express EMA-of-EMA and Supertrend without loops or eval; three v1 mines (Bollinger %B, Sparta, Pivots) are ported as composed or built-in indicators and match v1's formulas on a fixed candle set.
  Probe: test+property: composed EMA-of-EMA, Supertrend; v1 ports vs v1 formulas. Pass: match; no unclosed-bar reads. Tool: pytest + hypothesis.
- [ ] SEP-13.4: An indicator file exported from one install imports on another unchanged and keeps its content hash; the indicator list in the dashboard filters by category.
  Probe: test+browser: export → import on a second home; category filter. Pass: same hash; filter works. Tool: pytest + bun test + Chrome.
- [ ] SEP-13.5: An indicator published as a signed Nostr event installs on another engine by fetch plus hash check; the author's SA address is shown; a tampered or re-signed copy is refused.
  Probe: integration: publish, fetch, tamper. Pass: installs; tampered refused. Tool: pytest + relay.
- [ ] SEP-13.6: Candle storage keeps only 1m bars as Parquet (no duplicate raw archive after a checksum-verified conversion); higher timeframes and indicator outputs are computed, never stored; one pair-year of 1m BTCUSDT stays under 40 MB.
  Probe: test: catalog after conversion; size of 12 months. Pass: no raw zip left; < 40 MB. Tool: pytest + du.
